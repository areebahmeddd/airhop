In plain words

Explain it to a ten year old

Imagine building with Lego instead of clay. With clay every piece is whatever shape your hands made that day, so nothing quite matches anything else. With Lego every piece comes from a small set of sizes, so anything you build fits together without you thinking about it. The app is built from a small set of sizes: nine spacings, nine text sizes, seven corner roundings, one accent colour. Nobody picks a number. They pick a piece.

The governing rule

The rule, from .github/skills/ui-ux.md

A value is right when a rule produced it and wrong when somebody picked it.

Quality lives in the relationships between elements, not in any element: radius against padding, target against the thing it represents, one gesture's timing against the same gesture elsewhere. None of it shows in a screenshot; all of it shows in the hand.

The corollary is the part that actually holds a codebase together: solving something once is half the job. It is finished when the answer is a token, a shared component, or a lint rule. Every drift in this codebase was a correct decision that never propagated.

That is a testable claim, not a slogan. A hand-typed 50 sitting next to BUTTON_HEIGHT is evidence that somebody eyeballed it, and it is the shape of every inconsistency that ever shipped.

theme.ts, the whole vocabulary

412 lines, one file: src/ui/theme.ts. Every scale is deliberately short, because a scale long enough to contain the value you wanted is a scale that has stopped constraining anything.

ScaleValuesWhy these
Spacing 4, 8, 12, 16, 20, 24, 32, 48, 64 A 4pt grid, the common denominator of the iOS 8pt grid and Material's 4dp grid. Nine steps covers a phone; a tenth would be someone splitting the difference.
FontSize 10, 11, 13, 15, 17, 20, 24, 30, 38 10 is glyph-only: unread counts and radar ring labels, never anything a person reads. Anything readable starts at 11. Nothing below 10 exists, because a 9pt digit is illegible and has no token to justify itself.
Radius 2, 6, 10, 14, 20, 28, full Steps of 4 up to 14, then wider. Built so that outer minus padding lands on another token (see below). full is 999, so a circle is never a hand-halved size.
Duration 180, 220, 700 One motion vocabulary so a list reorder, a sheet dismissal and a toast fade read as one app moving. 700 is the pull-to-refresh hold, because the work itself returns instantly and a flash-then-gone spinner reads as broken.
FontWeight 400, 500, 600, 700 Four, named. No 300, no 800: a weight nobody can distinguish from its neighbour is a decision with no output.
Shadow low, medium, high Three elevation steps rather than a hand-tuned shadow per component. Each names what it is for: a thumb lifted off its track, a pill floating over content, persistent chrome.
MaxFontScale chrome 1.4, badge 1.2 Caps on OS text scaling, and each names the fixed container it protects. Body copy is uncapped on purpose.

Beside the scales sit the single-value constants, each one existing so that a dozen call sites cannot each pick their own:

ConstantValueReasoning recorded in the file
MIN_TOUCH44Apple's 44pt and Material's 48dp round to the same practical floor. WCAG 2.5.8 asks 24x24 minimum with 44x44 as the AAA target.
BUTTON_HEIGHT50Past the floor, because full-width buttons are stacked commitments, several destructive, so there is no adjacency to resolve and the height is free.
LONG_PRESS_MS320Under React Native's 500ms default, which is tuned for a rare secondary menu rather than the message actions this opens.
PRESSED_OPACITY0.85For a surface with nothing neutral to darken: an accent fill, or a bare icon and label.
DISABLED_OPACITY0.4The floor at which a glyph still reads as a shape, so the affordance survives while clearly not inviting a tap.
HIT_SLOP8 all roundThe default forgiveness for a control that is already comfortably sized.
TAB_BAR_CLEARANCE96The bottom padding a scrollable tab screen leaves so its last rows clear the floating tab bar instead of scrolling under it.

hitSlopFor(visualSize) is the escape hatch that keeps the rule intact rather than breaking it: a 32pt header glyph stays 32pt on screen and becomes 44pt to a thumb, computed rather than typed.

Colour: one accent, meaning only

The colour rule, stated in the first six lines of theme.ts

If a colour does not communicate information, it should not exist.

The result is a monochrome app with exactly one interactive accent (near-black on light, near-white on dark) and a small set of colours that are each locked to one meaning:

ColourMeans, and only ever means
Green e2ee, online, successEnd-to-end encrypted; a peer is reachable; an operation worked.
Blue verifiedA verified contact. Never anything else, so a blue shield always reads one way.
Amber syncingScanning, or reconnecting. Caution, not failure.
Red dangerDestructive. The panic wipe, and deletions.
Blue relay, violet tor, teal gateway, indigo bridgeFour distinct network states on the Mesh tab, each hue naming one, so the tab reads at a glance.

Two colour decisions in that file are worth reading as examples of the general method, because both started as bugs:

The selection colour is not the accent

The accent is a solid near-black, and a text field paints the selection as an opaque block behind the glyphs. Using the accent meant selecting a whole message hid the text under a slab. The fix is rgba(17,17,17,0.18): enough alpha to show the run, little enough to keep every glyph readable. The dark palette carries 0.24 instead, because a pale wash on a near-black canvas reads fainter than the same alpha of black on white.

The offline dot is not pale grey

A #CCCCCC dot measures 1.6:1 on a white row and simply cannot be seen, which makes "this peer has gone quiet" unreadable at exactly the size it matters most. A status dot is a meaningful UI indicator, so it owes 3:1 against its own background under WCAG 1.4.11. The token is #909090.

The three text greys carry their measured ratios in a comment beside them, against #F8F8F8, the worse of the two surfaces they sit on: 

  textPrimary    #111111    17.4 : 1     AAA
  textSecondary  #565656     7.0 : 1     AAA
  textMuted      #6F6F6F     4.8 : 1     AA   <- timestamps, placeholders

  the pair that failed, and why the note exists:
  #666666 / #8A8A8A  ->  3.2 : 1   under AA, on every timestamp,
                                    scope line, placeholder and label

The recorded fix is "darken rather than restructure, keeping the same hue and the same three-step hierarchy". That sentence is the method: the constraint moved a value, it did not redesign the screen.

Two palettes, one set of keys

Colors and DarkColors hold identical keys, so a screen swaps the entire palette by swapping which object it reads. Nothing imports either one directly. Everything calls useThemeColors(), which is what makes the theme setting apply everywhere rather than in the screens somebody remembered. 

  useThemeColors()
        │
        ├─ preference: "light" | "dark" | "system"
        ├─ systemScheme from useColorScheme()
        ├─ resolveTheme(preference, systemScheme)   "system" is the
        │                                           ABSENCE of a choice,
        │                                           resolved here once so
        │                                           two callers cannot
        │                                           disagree
        └─ returns { ...Colors } or { ...DarkColors }

  monoFont is part of the memo identity on purpose: it does not change
  the palette, but a fresh object forces every memoized style to
  recompute and re-read FontFamily.mono, so a font change applies live
  exactly like a theme switch.

Dark mode is not a filter over the light palette. Three things are re-derived rather than inverted:

  • Elevation direction flips. On light, surfaceRaised is darker than surface. On dark it is lighter. A naive lift inverts, so anything raised has to be checked against its own track in both themes.
  • Shadows stop working. Black on #0B0B0B is invisible, so anything relying on a shadow for separation carries a hairline border too. The tab bar and the transfer pill both do.
  • Every -Dim carries more alpha. 0.09 on light becomes 0.16 on dark, because a low-alpha wash disappears on near-black.

Concentric radius

The single most-cited detail in the skill file, and the one most visible when it is wrong. 

  inner radius  =  outer radius  -  padding


   correct                        wrong (inner too large)
   ┌────────────────────┐         ┌────────────────────┐
   │  ╭──────────────╮  │         │ ╭────────────────╮ │
   │  │              │  │         │╱                  ╲│
   │  │   constant   │  │         │    corners bulge   │
   │  │   gap round  │  │         │    toward each     │
   │  │   the corner │  │         │    other           │
   │  ╰──────────────╯  │         │╲                  ╱│
   └────────────────────┘         └────────────────────┘

A rounded box inside a rounded box holds a constant gap around the corner only at that value. Too large and the corners bulge toward each other; too small and they pinch. The eye registers it without naming it, which is exactly why it is worth getting right: nobody will report it and everybody will feel it.

The scale is built so the arithmetic lands on tokens. Radius.lg (14) minus Spacing.xs (4) is 10, which is Radius.md. Minus Spacing.sm (8) is 6, which is Radius.sm. Above lg they stop lining up, so the instruction is to compute the value rather than reach for the nearest token. A hand-typed radius sitting next to a token is the tell.

Targets match their meaning

Fitts's Law, applied literally: if a row means "this message", the whole row acts like it. A one-word bubble is a 40pt target inside a full-width row, and the rest of that row must not be inert. 

  three ways to reach MIN_TOUCH, in order of preference

  1. measure it            the control is genuinely 44pt or more
  2. hitSlopFor(size)      32pt glyph, 44pt to a thumb, unchanged
                           on screen
  3. padding / negative    where hitSlop cannot reach (inside a
     margin                scroll view's own hit testing)

     padding: (MIN_TOUCH - SIZE) / 2
     margin: -(MIN_TOUCH - SIZE) / 2

Grow height only, when targets are adjacent

Two 44pt-wide targets whose centres are 24pt apart overlap, and then view order decides the winner rather than the finger. That is worse than the small target was, because it is non-deterministic from the user's point of view: the same tap in the same place hits different things depending on render order.

Every tap reports

Nielsen's first heuristic, visibility of system status, and both platforms require it: UIKit highlights a selected cell, Material draws a ripple. A tap that changes nothing until the next screen arrives reads as broken on a slow push, and gets tapped twice.

Two treatments, chosen by what the surface already is:

SurfaceTreatmentWhy the other one fails
A neutral fill of its own: a row, a raised pill Darken to surfacePressed A row cannot dim. A white row on an off-white page loses nothing visible.
An accent fill, or no fill at all: a tab, a segment Dim to PRESSED_OPACITY An accent button cannot darken. Its fill is the accent, so darkening means recolouring the label, which reads as a state change rather than a press.

Always through Pressable's style={({ pressed }) => ...} callback, never component state, which re-renders twice per tap. Feedback under 400ms is the point (Doherty's threshold); anything slower needs its own progress indicator.

Optical, not mathematical

Four places where the correct number and the correct-looking number differ. All four are recorded because all four were shipped wrong once.

EffectWhat goes wrongFix
Letter-spacing Tracking is applied after the last glyph too, so a tracked string measures wider than it draws. Centring that box leaves the glyphs half a track short. marginEnd: -TRACKING, or trim the trailing padding on a pill.
includeFontPadding Android-only and on by default. It reserves ascender and descender room a digit never uses, so a numeral that centres on iOS sits low on Android. includeFontPadding: false on any digit centred in a circle.
One-sided nudges An optical nudge on one side makes the box asymmetric, so text centred inside it lands off by half the nudge. Every nudge needs its mirror on the other side.
Display figures Default 1.1 leading at 38pt leaves a band of dead space under the digits. Pull leading in to the font size, with slight negative tracking.

UIKit's separatorInset and Material's divider keyline agree on this, which is the usual sign that a convention is about perception rather than about a platform.

The companion rule: things that are the same object must match in every property. Three badges at the same size with three different line heights are three objects to the eye, not one object shown three times.

The measurement mistake worth naming

Measure against the surface the element actually sits on, not the page. Text on a selection wash is on the wash, not on the row, and not on the background behind the row. This is the single most common way a palette that "passes" still produces unreadable text.

A disabled control is allowed to be a dim rather than a colour change, because WCAG 1.4.3 exempts inactive controls. But every disabled control also carries accessibilityState.disabled, so it is never dim alone: the state is available to a screen reader that cannot perceive opacity at all.

Motion and haptics

Durations come from Duration so a list reorder, a sheet dismissal and a toast fade read as one app moving rather than three components each guessing. Reanimated defaults to ReduceMotion.System and needs no second gate; Animated.loop does, through useReducedMotion().

Haptics are the part of this system that generalises least and is therefore most carefully constrained. They are named by the situation that earns them, never by feedback type, and importing expo-haptics directly is blocked by an ESLint rule.

VerbThe situation that earns it
acknowledged()A silent action landed. Copying is the case that matters: the only visual confirmation is a glyph under the thumb that just covered it.
held()A press-and-hold crossed its threshold. The only gesture with no visible progress, so the tick is what confirms the hold is working.
released()A hold ended. The light counterpart, closing the pair a press-and-hold opens.
crossedThreshold()A drag passed the point where letting go closes rather than springs back. The sheet's dismiss line is invisible; this is the only thing marking it.
armed()A hold crossed into "let go now and this is thrown away": sliding a push-to-talk recording back to cancel. Rigid rather than a tick, because push-to-talk is used without looking and the destructive threshold has to be tellable apart by feel.
succeeded()Something completed while the user may not be watching the screen. Scanning is the case: the phone is held up at another display.
rejected()A check refused something the user must register: a card whose keys do not match its own peer ID. Not for "that was not a QR code".
warned()Something irreversible happened with no dialog in front of it. The panic wipe's triple tap is the only one, and this is its only confirmation.

Every call is fire-and-forget: a device with no motor, a simulator, or a declined vibration permission all reject, and none of that is actionable, so it is swallowed once in that module rather than at each call site. Haptics are deliberately not wired to reduce-motion, because that setting is about animation and haptics are what the app falls back to when motion is off.

Speaking the user's language

Nielsen's second heuristic, and the one this app is most exposed to, because it has more protocol vocabulary than almost any consumer application. The rule is absolute: never surface protocol vocabulary.

The example the skill file uses

"0 mints, 0 proofs" is the wallet describing its own plumbing in the most prominent slot on the screen. A user has no word for a mint and no word for a proof, and the sentence tells them nothing about whether they have money.

Three corollaries follow from it:

  • Say nothing rather than something empty. A card with nothing to report reports nothing. The conditional notes that appear only when relevant are the ones that read as personal.
  • An alert must earn its tap. An alert demands acknowledgement for news nobody needs to acknowledge. Confirmations use Toast or an in-place tick; alerts are kept for information the user must act on.
  • Never delete real information just to remove a dialog. The fix for a noisy alert is a quieter surface, not less truth.

Copy style, from the design principles: terse, plain, no exclamation marks, no jargon where a plain word exists.

The ten heuristics, scored

Nielsen's ten, each with where it shows in this app and an honest note where it is only partly met. Chapters are linked for the long version.

7 Flexibility and efficiency of use Long-press message actions at 320ms rather than 500. One unified search across every thread. Paste, camera and manual entry all reach the same add-contact confirm.

9 Help users recognise, diagnose and recover from errors A blocked permission produces the reason plus a Settings deep link, not a dead end. Being honest about number 10

There is no in-app help, no onboarding beyond the permission primer, and no explanation of what a courier is or why a message might take a day to arrive. For an app whose core mechanics are genuinely unfamiliar, that is a real gap rather than a stylistic choice, and it belongs on the roadmap alongside the review findings in 49.

The laws, and where each one shows

The named laws from lawsofux.com, each with the specific decision in this codebase that it produced. A law with no decision attached to it is decoration, so any law that did not change something here is left out.

LawWhat it saysWhat it produced here
Fitts's Law Time to acquire a target is a function of its distance and size. MIN_TOUCH 44, hitSlopFor(), and the rule that a row meaning "this message" is tappable across its full width. Also the rule to grow height only when targets are adjacent.
Doherty threshold Interaction stays engaging below about 400ms of response. Pressed feedback on every tap, applied through the style callback so it is immediate. Anything slower gets its own progress. Duration.base at 180ms sits comfortably inside the threshold.
Jakob's Law People spend most of their time in other apps, and expect yours to work the same way. The entire borrowed-conventions table below. Delivery ticks, long-press menus, a WhatsApp-style profile drill-down, one unified search surface.
Hick's Law Decision time grows with the number and complexity of choices. Four tabs. Nine spacing steps. Four font weights. One accent. Settings grouped into sub-screens rather than one long list.
Law of Common Region Elements inside a shared boundary are perceived as a group. Card surfaces with hairline borders, and the separator inset rule that keeps the icon column reading as a channel rather than being sliced.
Law of Proximity Things close together are perceived as related. The 4pt grid itself. Gaps inside a group are one step; gaps between groups are two or more.
Law of Similarity Visually similar elements are perceived as related. "Things that are the same object must match in every property." Three badges with three line heights are three objects.
Law of Prägnanz The eye resolves ambiguous forms into the simplest available reading. Concentric radius. A constant corner gap resolves as one nested shape; a wrong inner radius resolves as two shapes fighting.
Aesthetic-usability effect People perceive attractive designs as more usable, and forgive their faults. Treated as a warning rather than a licence. This is why the review chapter separates "looks finished" from "is finished", and why an unaudited protocol is labelled unaudited on the index page.
Tesler's Law Every system has irreducible complexity; the only question is who absorbs it. The app absorbs it. Transport selection, session state, courier spraying and mint reconciliation are all invisible. The user sends a message; the ladder underneath is 15.
Postel's Law Be liberal in what you accept, conservative in what you send. The add-contact screen accepts three code formats and a bare peer ID; it emits exactly one. TLV skips unknown types by length rather than failing.
Miller's Law Working memory holds about seven items. Eight haptic verbs, four tabs, three elevation steps, three text greys. Every vocabulary in this system is deliberately memorable in one sitting.

Where it deliberately does not follow

Colour is the divergence. Every app in that table uses a brand hue as its accent; Airhop uses near-black and reserves colour for meaning. That is not minimalism for its own sake: this app has more genuinely meaningful states than a normal messenger (four network modes, two trust levels, three delivery states), and a brand colour competing with them would make the meaningful ones harder to read.

How this is enforced

The corollary from the top of the chapter says a decision is finished when it becomes a token, a shared component, or a lint rule. All three exist here.

MechanismWhat it makes impossible
Tokens in theme.ts A literal 50, 320 or 0.85 in a style block. Every one of them has a name.
useThemeColors() A screen that ignores the theme setting, because importing Colors or DarkColors directly is the only way to hard-code one and it is called out as a mistake.
Eleven shared components A hand-rolled Modal for a sheet, which drifts in behaviour and usually ships a grab handle that ignores the finger. BottomSheet owns the drag, the scrim, keyboard avoidance and back-button dismissal, so converting a sheet means deleting boilerplate rather than restyling.
ESLint no-restricted-imports Importing expo-haptics directly. The message names all eight verbs and tells you to add one with a comment if none fits.
The skill file Rediscovery. .github/skills/ui-ux.md is 142 lines and is meant to be read before adding a component, a style block, or any tappable surface.
The pseudolocale A layout that only works in English. It pads every string past the longest real translation. Chapter 40.

What breaks it

  • A Pressable with no pressed style. The most common defect, and it fails silently: on a fast device nobody notices, and on a slow push it reads as broken and gets tapped twice.
  • Contrast checked against the page. Passing on the background and failing on the surface the element actually sits on. Selection washes and raised surfaces are where this bites.
  • A naive dark-mode lift. surfaceRaised is darker than surface on light and lighter on dark, so an elevation that was derived by hand inverts in one theme.
  • The same object styled in two files. This is how every drift in the codebase started: a correct decision that never propagated into a token or a component.
  • A setState on a timer with no cleanup. Sheets close fastest right after a tap, which is exactly when a pending timer fires into an unmounted tree.
  • Adjacent targets grown in both dimensions. Two overlapping 44pt targets hand the decision to view order rather than the finger, which is worse than the original small target.

If you removed it

The app would keep working and would slowly stop feeling like one app. That is the honest answer: no user-visible failure on day one, and after twenty screens a set of surfaces whose corners, gaps, press treatments and timings each came from whoever wrote that screen. The specific losses are measurable, though: without useThemeColors() the dark theme applies only where somebody remembered it; without the contrast comments the greys drift back toward the 3.2:1 pair that failed; without MIN_TOUCH and hitSlopFor the small glyphs become genuinely hard to hit on a moving bus, which is a disproportionate cost for the people this app is built for.

Alternatives

ApproachHow it worksWhy not here
Tailwind or NativeWind Utility classes with a config-defined scale Gives the scale but not the reasoning. The value of this system is the 200 lines of comments explaining why each number is that number, and a utility string has nowhere to put them. It also adds a build step to a bare-workflow app that deliberately has few.
A component library (Tamagui, RN Paper, gluestack) Pre-built components with their own theming You inherit someone else's opinions about press feedback, sheet behaviour and elevation, and then fight them at every point where this app differs. Eleven hand-written components is less code than the overrides would be.
A brand accent colour The convention every app in the borrowed table follows This app has four network states, two trust levels and three delivery states that all genuinely need to be distinguishable. A brand hue competing with them makes the meaningful colours harder to read.
Design tokens generated from Figma A pipeline exports the palette and scales into code Correct at a larger organisational scale, where the design and the code are maintained by different people. Here it would move the reasoning out of the file where the value is used, which is the opposite of what makes this work.
Documented conventions, no enforcement A style guide, reviewed by humans This is the state every drift in the codebase came from. The skill file exists and the lint rule exists, because a convention that only lives in prose is rediscovered rather than followed.

Drills

  • A designer asks why the inner radius of a card inside a card is not simply the same as the outer one. Because a constant visual gap around a corner only happens at inner = outer - padding. Equal radii mean the gap is widest at the corner and narrowest along the edges, which the eye reads as two shapes fighting rather than one nested inside another. Too large and the corners bulge toward each other, too small and they pinch. It is a Prägnanz effect: nobody names it and everybody feels it. The scale is built so the subtraction lands on tokens up to Radius.lg, and above that the instruction is to compute the value rather than reach for the nearest one.
  • Why do rows darken on press while accent buttons dim? Because each treatment fails on the other surface. A row cannot dim: a white row on an off-white page loses nothing visible at 0.85 opacity. An accent button cannot darken: its fill is the accent, so darkening it means recolouring the label too, and a label changing colour reads as a state change rather than a press. So the treatment is chosen by what the surface already is, neutral fill or accent fill, and both go through Pressable's style callback rather than component state, which would re-render twice per tap.
  • The palette passes a contrast checker but users report unreadable text. Where would you look first? At what the text is sitting on when it fails, rather than at the palette. The most common error is measuring against the page instead of the surface the element actually occupies: text on a selection wash is on the wash, not on the row and not on the background behind it. The second candidate is dark mode elevation, where surfaceRaised is lighter than surface rather than darker, so a value derived by hand for light mode inverts. The third is a non-text element judged by the 4.5:1 text rule when it owes 3:1 under WCAG 1.4.11, or the reverse: a status dot at 1.6:1 passes nothing and is exactly the case where the information matters most.
  • Why are haptics named armed() and held() rather than heavy() and medium()? Because naming by feedback type guarantees drift: two call sites that mean the same thing to the user pick different buzzes, and nothing in the name says they should have matched. Naming by situation makes the vocabulary the unit. It also forces the reasoning to be written down, which is where the interesting decisions live: armed() is rigid rather than a tick specifically because push-to-talk is used without looking at the screen, so the destructive threshold has to be tellable apart from the ordinary one by feel alone. The rule is enforced by ESLint rather than convention, and the error message names all eight verbs.
  • Which of Nielsen's ten does this app meet least well, and what would you do about it? Number ten, help and documentation. There is no in-app help, no explanation of what a courier is, and nothing that tells a user why a message might take a day to arrive. For an app whose core mechanics are genuinely unfamiliar, that is a real gap rather than a stylistic choice. The fix is not a help centre: it is contextual, one sentence at the moment the unfamiliar thing happens. A message that has gone to a courier should say what that means, once, where it happens. That is also consistent with the rule that a card with nothing to report reports nothing, because the note only appears in the situation it explains.
  • Justify a monochrome palette to someone who thinks it looks unfinished. The constraint is not aesthetic, it is informational: if a colour does not communicate information, it should not exist. This app has more genuinely meaningful colour states than a typical messenger, four network modes, two trust levels, three delivery states, and a brand hue competing with them makes the meaningful ones harder to read. A green padlock always means encrypted and a blue shield always means verified precisely because nothing decorative is allowed to be green or blue. The trade is real and worth naming: the app is less immediately distinctive than one with a brand colour, and it depends more on typography and spacing to feel finished, which is why the token discipline matters more here than it would elsewhere.
  • A reviewer says the design system is over-engineered for a phone app. Answer them. The whole system is one 412 line file, eleven shared components and a single lint rule, and most of those 412 lines are comments recording why a value is what it is. That is less code than the overrides a component library would need. The cost is small; the thing it buys is that a decision made once propagates, which is the only mechanism that keeps twenty screens looking like one app. The evidence is in the file itself: the selection colour, the offline dot and the three text greys were each shipped wrong, fixed once, and turned into a token with the reasoning attached, so none of them can be re-decided by the next person.
